# Tutorial: catch a regression with one of three test files

This exercise runs the installed CLI and real pytest processes against a temporary
Git repository. It needs Python 3.14+, Git, and the development dependencies.

```bash
git clone https://github.com/gigaverse-app/pytest-selective.git
cd pytest-selective
uv sync --locked
uv run python scripts/tutorial.py --output tutorial-report.json
```

## 1. Start with a passing shop

The [script](../scripts/tutorial.py) creates three test files and commits them.
`test_checkout.py` imports `shop.checkout`, which imports `shop.prices.total`.
The other two test files have no pricing dependency. It runs the complete suite
first and requires it to pass.

## 2. Introduce a real regression

The script changes `total(3)` from 6 to 9 and commits the change. It invokes:

```bash
python -m pytest_selective affected --config impact.json \
  --base BASE_SHA --head HEAD_SHA --output selection.json
```

`BASE_SHA` and `HEAD_SHA` stand for the actual commits generated by the script.
The plan selects `tests/test_checkout.py` through its transitive import chain.
Running that test fails. The script requires this failure, so a selector that
misses the regression makes the tutorial fail.

## 3. Change documentation

The next commit edits only an unreferenced README. Comparing with the immediately
preceding commit yields `none` and an empty list. The runner skips pytest.
The earlier pricing defect remains: an empty plan means no affected tests for
this delta, not that the repository is healthy. In real CI, use a known passing
base or preserve unresolved failure canaries.

## 4. Change shared startup code

A root `conftest.py` changes. All three files are selected because they all load
it. Pytest still finds the pricing regression. Shared fixtures are intentionally
conservative; keep fixtures close to their consumers to avoid unnecessarily broad
selections.

## Inspect the evidence

`tutorial-report.json` contains each pair of commit SHAs, selected paths, total
file count, selection reasons, and expected pytest outcome. CI runs the same
script on Linux, Windows, and macOS and retains its report as an artifact. The
[tutorial test](../tests/test_tutorial.py) also checks the user journey.

These three tiny cases demonstrate selection behavior, not production speed.
For your own project, compare full and selected runs on the same revisions,
record cold and warm planner time, and investigate any missed failure before
making selection a gate. Continue with [configuration](configuration.md).
